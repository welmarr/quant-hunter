# Private research results and deliberate sharing

The native application is a private loopback workspace. Authentication does not
create a public sharing link. Each account can read only its own operational jobs,
owned datasets, papers and research results; owner maintenance authority does not
silently grant access to another user's private research. Shared instrument and
source capability catalogues contain reference metadata, not private run payloads.

## Choose the smallest review artifact

For a review, prepare a separate sanitized report containing the question,
permanent experiment/model/pattern IDs, exact code and configuration digests,
method and data-vintage descriptions, declared costs, all tested variants,
failures, software evidence and limitations. Preserve the distinction between
synthetic software tests, historical observations and prospective evidence.
Include sample size, dependence/selection limitations and unavailable metrics.
A screenshot of a good result is not an adequate scientific report.

Before copying source rows, chart values, publication text or a report containing
such content, verify that its recorded license permits that particular recipient
and redistribution. An uploader's declaration is not a license verification. If
rights are unknown, share methodology and non-sensitive provenance identifiers
without the underlying data. Do not describe an unreviewed result as validated,
tradeable or predictive. No repository mechanism promotes it to production.

## Never share a runtime backup as a report

`.qhbackup` archives, `.local` runtimes and application/paper/broker SQLite files
contain private accounts, password hashes, sessions, operational history and
source data. They are recovery artifacts, not research exports. Private vaults,
master keys, provider tokens, Telegram destinations, authentication cookies and
browser-test account files must be excluded from reports, screenshots and Git.
A visible masked value is not permission to expose its underlying stored value.
Use [OPERATIONS.md](OPERATIONS.md) and [CREDENTIALS.md](CREDENTIALS.md) for separate
recovery; do not combine key recovery material with an ordinary report.

The app does not send research to collaborators automatically. Telegram's
explicit owner test/configuration is an external notification capability, not a
private-results publishing system. SMS remains conditional. No real external
message or broker order is required to verify a local report.

## Reproducibility and correction

Retain the original immutable run and its source/configuration bindings. A
sanitized derivative should identify what was omitted; it must not rewrite the
original result, erase failed variants or claim a reduced variant count. Correct
mistakes by adding a new version and linking the predecessor. Sharing a report
does not release the sealed holdout or satisfy HOST_ENFORCED, empirical, Stage1,
production or real-money gates. Owner review of rights and privacy is required
before any deliberate external publication.
